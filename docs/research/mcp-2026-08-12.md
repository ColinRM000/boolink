# MCP research snapshot — 2026-08-12

This snapshot records the protocol facts used for BooLink's initial architecture. It should be
revisited before protocol-level changes.

## Findings

- MCP revision `2026-07-28` is released and introduces the modern, stateless protocol era.
- The official TypeScript SDK v2 is the stable line and uses split packages such as
  `@modelcontextprotocol/server` and `@modelcontextprotocol/client`.
- A constructed `McpServer` connected directly to an in-memory transport exercises the legacy era.
  Modern stdio serving must use `serveStdio(() => buildServer())`, which pins one server instance
  to the negotiated connection era.
- Stdio remains the correct transport for local, client-spawned integrations. Streamable HTTP is
  the remote transport. HTTP+SSE is deprecated.
- Roots, sampling, and protocol logging are deprecated for new work. Local stdio diagnostics belong
  on `stderr`.
- Modern MCP removes the initialize/session requirement, carries request identity in `_meta`, and
  supports explicit discovery. The SDK owns these wire-level differences.
- Tool schemas now support JSON Schema 2020-12. BooLink starts with Zod 4 object schemas and can
  widen the SDK boundary when a real integration needs more advanced schema composition.

## Architecture consequences

1. BooLink depends on official SDK v2 and does not reimplement MCP framing or negotiation.
2. Every runtime server is built from a side-effect-free factory so `serveStdio` can create a fresh
   instance per negotiated connection.
3. Integration code is independent of transport, enabling unit tests without spawning a client.
4. Foundation tests include a real client/server stdio smoke path for modern-era coverage.
5. Remote HTTP and OAuth are deferred until a concrete integration requires them.
